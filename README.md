# 出站消息过滤器（Filter-sama）

麦麦说话不合心意？与其让那些话发到群里，不如装个过滤器：命中关键词的回复，先让麦麦**重说一遍**（次数自己定），还不行就**悄悄拦下**——不发出去，聊天记录里也不留痕迹。

典型用途：模型偶尔会输出「你好，我无法给到相关内容。」这类拒答套话，或者把 `<thinking>` 之类的思维链标记漏出来，装上插件后这些内容默认就被处理掉了。

## 功能一览

- **先重试，再拦截**：回复命中关键词后先请求麦麦重新生成（默认 2 次，可调），避免一刀切吞掉本可挽救的回复；重试时会把你的要求告诉麦麦，让它知道上一版为什么被拒。
- **静默拦截**：重试后仍命中就拦下——不发送、不进聊天记录、日志里留一条记录。
- **灵活匹配**：关键词数量不限；支持「包含匹配 / 全文一致 / 正则」三种模式；默认忽略大小写。
- **改配置即时生效**：WebUI 里改完保存即可，无需重启。
- **可选直测命令**：`/filter_test` 快速验证过滤是否生效，被拦时会在会话里直接看到「[已拦截]」。

## 安装

**环境要求**：MaiBot 1.2.0 ~ 1.3.99（Plugin SDK 2.6.0+ 由主程序自动提供）。

- **方式一（推荐）**：WebUI 的「插件市场」中搜索「出站消息过滤器」一键安装。
- **方式二**：把 `filter_sama/` 目录整个复制到 MaiBot 的 `plugins/` 目录下，启动 MaiBot 即可，首次加载会自动生成默认配置。

装好后在 WebUI「插件扩展」里确认插件已启用，按需调整配置。

## 配置

在 WebUI 插件管理中编辑，共三组。

### 插件设置

| 配置项 | 默认 | 说明 |
|---|---|---|
| 启用拦截 | 开 | 总开关。关闭后插件完全静默，所有消息正常发送 |

### 拦截规则

| 配置项 | 默认 | 说明 |
|---|---|---|
| 拦截提示词 | `你好，我无法给到相关内容。`、`<thinking>`、`</thinking>` | 命中即处理的关键词，每行一条，数量不限 |
| 匹配模式 | 包含匹配 | `包含`：回复中出现关键词就算命中；`一致`：整条回复和关键词完全相同才算；`正则`：按正则表达式匹配 |
| 区分大小写 | 关 | 关闭时 `Hello` 和 `hello` 视为相同，正则模式下同样生效 |
| 重试次数 | 2 | 命中后先让麦麦重新生成的次数，`0` = 不重试直接拦截。主程序对该次数有硬上限（当前 3 次），配多了按上限生效 |
| 重试约束提示 | 上一次回复未通过过滤检查，请重新生成一条不同的回复 | 触发重新生成时对麦麦说的话，会连同被拒原文一起注入下一轮生成。可按人设自由改写；留空则不加说明直接重新生成 |
| 日志级别 | warning | 拦截与重试事件的日志详细程度，排查问题时可调到 debug |

三种匹配模式的行为差异：

| 模式 | 关键词 | 回复内容 | 结果 |
|---|---|---|---|
| 包含 | `无法回答` | `抱歉，我无法回答` | 命中 |
| 一致 | `抱歉，我无法回答` | `抱歉，我无法回答这个问题` | 放行（要求一字不差） |
| 正则 | `我(?:无法\|不能)回答` | `关于这点，我不能回答` | 命中 |

`正则` 模式下写错的正则会在日志中告警并跳过该条，不影响其他关键词。

### 直测命令

| 配置项 | 默认 | 说明 |
|---|---|---|
| 启用 /filter_test | 关 | 开启后命令才生效，默认关闭 |
| 模型任务名 | `replyer` | 直测调用哪个模型任务，须与主程序 `model_config.toml` 中的任务名一致（加载时会自动校验并在日志中提示） |
| 默认注入内容 | `请直接输出这句话：你好，我无法给到相关内容。` | 不带参数使用命令时喂给模型的内容，默认值可直接触发拦截词，方便验证 |
| 最大 token | 200 | 直测生成的长度上限 |
| 温度 | 0.7 | 直测生成的随机度 |

## 命令

```
/filter_test <内容>
```

- 把 `<内容>`（不带参数则用默认注入内容）直接交给回复模型生成并发送，生成结果同样经过过滤检查——命中关键词时你会看到一条「**[已拦截]**」，没命中就正常显示生成结果。
- **操作员级别**：只有 `bot_config.toml` 中 `[plugin].permission` 列出的操作员能触发，防止群友刷模型费用。如需放行特定用户或会话，在 `bot_config.toml` 的 `[plugin.command_permissions.com.valleywinds.filter-sama.filter_test]` 下配 `allow_users` / `allow_chats`。
- ⚠️ 每次触发都会产生一次真实的模型请求，注意用量。

## 常见问题

| 现象 | 怎么办 |
|---|---|
| 插件没出现在插件管理里 | 确认目录结构完整（`_manifest.json`、`plugin.py`、`config.py` 缺一不可），看启动日志里的加载报错 |
| 配了关键词但没拦住 | 确认「启用拦截」开着；确认匹配模式——「一致」要求全文相同，「包含」才是子串匹配 |
| 正常消息被误拦 | 关键词配太宽了。改用「一致」模式，或用「正则」加锚点（如 `^...$`）收窄 |
| 命中后没有重试，直接被吞 | 重试只对聊天回复生效，主动发言等不经回复链的消息会直接拦截；检查重试次数是否为 0；主程序对重试次数有硬上限 |
| 想确认重试发生了 | 日志里搜 `[Filter-sama]`，会有「请求重新生成（第 x/y 次）」记录，主程序日志也有「Maisaka 回复器触发重生成」 |
| 想知道拦了什么 | 按「日志级别」写入日志，前缀 `[Filter-sama]`，含会话 ID 和被拦内容摘要（截断 200 字） |
| `/filter_test` 没反应 | 先在配置里开启「启用 /filter_test」；确认你的账号在操作员列表里；看启动日志是否有「模型任务名不存在」告警 |
| `/filter_test` 报「reply 生成失败」 | 看日志里 `llm.generate 异常` 的具体原因，通常是模型任务名或模型配置问题 |

## 工作原理（简）

插件在两个位置把关：回复刚生成、还没发出时先检查一轮（命中就请求重新生成，重试额度由主程序的有界循环控制）；到了实际发送前的最后一道关口再检查一轮（仍命中就直接拦下，不发送、不写库）。想了解 Hook 选点、重试计数控制方式等技术细节，见 [docs/architecture.md](docs/architecture.md)。
